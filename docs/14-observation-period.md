## 1. 缺陷標記紀律（Q08-2 解決）

### 1.1 兩個標籤

| 標籤 | 意義 | 什麼時候貼 | 誰貼 |
|---|---|---|---|
| `defect/escape` | **缺陷逃逸**：合併後才被發現的缺陷（本應在審查/測試中被攔下） | 發現合併產物有 bug 時，貼在**修正該 bug 的 Issue** 上 | 發現者（人） |
| `defect/review` | **審查攔截**：在人類審查 factory PR 時發現的缺陷（未逃逸，但代表 agent 品質問題） | 審查時發現問題，貼在**該工作項 Issue** 上 | 審查者（人） |

### 1.2 標記規則

1. **defect/escape 的判定**：合併後的功能性 bug，且可追溯到某顆 factory PR（`Closes #N` 連結）→ 貼 `defect/escape` 並在 Issue 留言標明來源 PR。
2. **defect/review 的判定**：審查 factory PR 時發現的邏輯/契約/測試錯誤 → 貼在該工作項 Issue，並以 review comment 記錄。
3. **兩者都必須可追溯**：`defect/escape` 的 Issue 必須 `Closes` 或提及來源 PR；`defect/review` 的 Issue 即工作項本身。
4. **不貼**：測試未涵蓋的既有程式碼缺陷（非 factory PR 引入）——那是另一回事，不計入 factory 的缺陷率。

### 1.3 指標定義（對照 docs/08 §2.4）

```
缺陷逃逸率 = defect/escape 數 / 期間內合併的工作項數
審查攔截率 = defect/review 數 / 期間內合併的工作項數
```

- 分母：有合併 PR 的工作項（`meta/observation` 期間內的）
- 觀察期內**合併工作項應貼 `meta/observation`**，讓分母可機械篩選
- 目標（Phase 2 的參考門檻，待校準——Q08-2 的後續）：逃逸率 0 才談自動合併（docs/09 §4 進入條件）

## 2. 觀察期機制

### 2.1 節奏

| 節奏 | 動作 | 產出 |
|---|---|---|
| **每顆 factory PR 合併時** | 審查者確認是否貼 `defect/review`（若有） | 即時標記 |
| **每週** | 檢查新增的 `defect/escape`/`defect/review`（`gh issue list --label defect/escape`）| 週報一行 |
| **每期結束（Phase 2 前）** | 依 §2.4 PDCA 流程做期檢（兩率 + 五問 → 缺陷分類 → 根因 → 預防行動） | 期檢紀錄（含 §2.4 追蹤表，攜入下期驗證） |

### 2.2 觀察期的啟動

- **啟動條件**：本機制文件合併後即啟動。
- **期間**：建議 2–4 週，或累積 ≥10 個帶 `meta/observation` 的合併工作項（兩者先到者）。
- **期間活動**：正常投放工作項（Phase 1 已驗證的 `agent-add-tests` 類別）、人類照常審查、標記照常進行。
- **結束動作**：計算兩率 → 更新 `13-phase1-acceptance.md` §6 → 作為 Phase 2 規劃的數據輸入。

### 2.3 誰負責

- **標記**：審查者（貼 defect/review）、發現者（貼 defect/escape）——目前即 philipz。
- **週檢**：可自動化一半（`gh issue list --label defect/escape --state open` 一行指令），人工解讀。
- **期檢**：依 §2.4 模板人工執行——模板的追蹤表（C/D 段）是 Act 環節的唯一載體，期檢紀錄本身不產出數據就沒有閉環。

### 2.4 期檢模板（PDCA）

> **為什麼要升級**：docs/09 §6 的五問只有 Check 環節——數字讀完、問題答完，一期的檢視就結束。缺陷被標記了，但「哪道防線沒攔住、機制怎麼改、改完有沒有用」沒有人負責；沒有 Act，改善行動就不被追蹤、不被驗證，同類缺陷會在下期再次逃逸。本模板把期檢從「答五問」升級為閉環：**缺陷分類 → 根因 → 預防行動 → 下期驗證**（依據：SWEBOK v4 Ch10 §3.1 PDCA、Ch12 §2.4.1 缺陷特徵分類、Ch18 §9 根因分析；Q19-5 裁決：**追蹤欄位內建於本模板，docs/08 只定義「預防行動完成率」衍生指標**）。
>
> **邊界**：分類只使用 §1.1 既有標籤與 Issue 資料——**不新增標籤、不改 §1 標記紀律**。

#### 期檢流程（每期執行一次）

| # | 環節 | 動作 |
|---|---|---|
| 1 | **Plan**（上期輸入） | 取出上期模板 D 的「驗證結果」欄：完成了嗎？有效嗎？→ 算入 A 段完成率；未完成者必須確認新的目標期 |
| 2 | **Check**（數據） | §1.3 兩率 + docs/09 §6 五問；缺陷清單 `gh issue list --label defect/escape --state all`（`defect/review` 同理；`scripts/weekly-metrics.sh` 已涵蓋週檢的資料蒐集） |
| 3 | **Check**（分類） | 對每期每個缺陷回答「分類三問」，填入模板 B |
| 4 | **Check**（根因） | 對影響最大的 **1–3 個**缺陷（非全部）做根因追溯，寫入模板 C——要追到**機制層**，不是行為層 |
| 5 | **Act**（預防行動） | 每個根因對應至少一個可驗證的預防行動：負責人、完成標準、目標期，填入模板 D |
| 6 | **Act**（攜入下期） | 期檢紀錄歸檔；下期步驟 1 逐項驗證——**沒被驗證的行動視為未發生** |

**分類三問**（步驟 3，每個缺陷都要答）：
1. **來源**：這是哪種任務型別的產出缺陷（Issue 宣告的 `agent-*` 型別；非 factory PR 引入者不計入——§1.2 規則 4）？
2. **防線**：哪道防線本應攔截而未攔（agent 自審 → 人類審查 → CI 閘門 → 合併後觀察）？
3. **根因類**：落入下表哪一類（用既有詞彙，否則跨期無法比較分布）？

**根因分類詞彙**：

| 類 | 含義 | 典型修正對象 |
|---|---|---|
| `spec` | 驗收條件不明/被誤讀，agent 猜測續做 | Issue 模板、factory-issue-check 閘門 |
| `skill` | docs 或 skill 誤導 agent | 對應 docs／`.dsh/skills`（人類修訂） |
| `test` | 測試未涵蓋該行為 | docs/11 策略、具體斷言 |
| `review` | 人類審查放過 | docs/07 §6.3 審查紀律、PR 尺寸 |
| `ci` | CI 該擋沒擋 | workflow、required checks |
| `infra` | 環境/工具故障（token、沙箱、逾時） | factory-run、scripts |

#### 期檢模板（每期复制到期檢紀錄使用）

````md
## 期檢 <期次>（YYYY-MM-DD）

### A. 數據（Check）
- 合併工作項 N；defect/escape N；defect/review N
- 逃逸率 __% / 攔截率 __%（§1.3）
- 五問（docs/09 §6）逐題回答：……
- 預防行動完成率 = __/__ = __%（定義見 docs/08 §2.4；本期無到期行動則記「不適用」）

### B. 缺陷分類（Check）
| 缺陷 Issue | escape/review | 來源任務型別 | 失效防線 | 根因類 |
|---|---|---|---|---|

### C. 根因（Check，影響最大的 1–3 項）
- <Issue #N>：<因果鏈一句話——這道防線為什麼沒擋住>

### D. 預防行動（Act，下期步驟 1 逐項驗證）
| # | 來源根因 | 預防行動 | 完成標準 | 負責人 | 目標期 | 驗證結果（下期填寫） |
|---|---|---|---|---|---|---|
````

**行動紀律**（讓 Act 可追蹤，不流於口號）：
1. **行動必須指向機制**——修正對象是 docs／skill／CI／測試／任務模板；寫得出「下次請更小心」，代表根因還沒追到底。
2. **完成標準必須可觀察**——改哪個檔案、哪條斷言、哪個檢查；下期用一條指令或一眼可核。
3. **驗證結果只有三種**：完成／未完成（附原因與新目標期）／完成但無效（產生新行動）——**沒有「進行中」**。
4. **需要改程式碼或 CI 的行動另開工作項 Issue**（走正常工廠流程），模板 D 記入該 Issue 編號；期檢紀錄只做追蹤，不做實作。

## 3. 與既有機制的關係

| 機制 | 關係 |
|---|---|
| `oversight/*` 標籤 | 監督層級（agent 前）；`defect/*` 是事後品質（agent 後）。正交 |
| `needs-human` | 執行交還；`defect/review` 是審查中發現的問題——不同事件，可能同時存在 |
| `meta/observation` | 觀察期樣本標記，供分母篩選；與前兩者正交 |
| docs/08 §2.4 | 本文件把 §2.4 的指標**操作化**（標籤 + 節奏 + §2.4 期檢模板）；「預防行動完成率」的**定義**在 docs/08，**欄位**在本文件 |
